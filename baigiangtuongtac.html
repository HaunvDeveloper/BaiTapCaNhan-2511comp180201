Chương 1: Tổng quan

API là gì? (Ví dụ Nhà hàng)

Khách hàng

(Client / Browser)

Người có nhu cầu gọi món nhưng không thể tự vào bếp nấu.

Bồi bàn (API)

(Trung gian)

Mang Request (Gọi món) vào bếp.
Mang Response (Món ăn) ra bàn.

Nhà bếp

(Server / Database)

Nơi chứa nguyên liệu và thực hiện chế biến phức tạp để tạo ra món ăn.

Cấu trúc HTTP Request

// 1. Request Line (Hành động)
POST /api/login HTTP/1.1
// 2. Headers (Thông tin bổ sung)
Host: api.example.com
Content-Type: application/json
Authorization: Bearer eyJhbGci...
// 3. Body (Dữ liệu gửi đi - chỉ có ở POST/PUT...)
{
  "username": "nguyenvanhau",
  "password": "******"
}

Cấu trúc HTTP Response

Phản hồi từ Server trả về Client cũng bao gồm 3 phần chính.

// 1. Status Line (Trạng thái)
HTTP/1.1 200 OK
// 2. Headers (Metadata về dữ liệu trả về)
Server: Apache/2.4.18
Content-Type: application/json
Content-Length: 452
Date: Sat, 29 Nov 2025 10:00:00 GMT
// 3. Body (Nội dung phản hồi - JSON/HTML/File...)
{
  "message": "Đăng nhập thành công",
  "token": "abc123xyz..."
}

Status Line

Cho biết request thành công hay thất bại thông qua mã số (200, 404, 500...).

Headers

Mô tả loại dữ liệu (JSON/HTML), server, cookie, cache...

Body

Dữ liệu thực tế mà người dùng hoặc ứng dụng cần (Danh sách sản phẩm, thông tin user...).

Các mã trạng thái (Status Code)

2xx - Thành công

  • 200 OK: Thành công bình thường.
  • 201 Created: Đã tạo tài nguyên mới (sau khi POST).

4xx - Lỗi phía Client

  • 400 Bad Request: Gửi sai định dạng.
  • 401 Unauthorized: Chưa đăng nhập / Token sai.
  • 404 Not Found: Không tìm thấy trang/API.

3xx - Chuyển hướng

  • 301 Moved Permanently: URL thay đổi vĩnh viễn.
  • 302 Found: Chuyển hướng tạm thời.

5xx - Lỗi phía Server

  • 500 Internal Server Error: Lỗi chung không xác định.
  • 503 Service Unavailable: Server quá tải / Bảo trì.

Fetch API

Giao diện lập trình hiện đại thay thế cho XMLHttpRequest, sử dụng Promise giúp việc gọi HTTP request trở nên đơn giản, sạch sẽ và dễ đọc hơn.

fetch('https://api.example.com/data')
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error(error));

    const res = await fetch('https://jsonplaceholder.../users/1');

    renderUser(user);
  } catch (err) {
    console.error(err);
  }
}

DEMO 4. Render Sản Phẩm

Lấy mảng dữ liệu và dùng .map() để hiển thị lên HTML.

render.js fakestoreapi.com 
async function getProducts() {
  const res = await fetch('.../products?limit=4');
  const products = await res.json();

  document.getElementById('grid').innerHTML = 
    products.map(p => `
      <div class="card">
        <img src="${p.image}" />
        <h3>${p.title}</h3>
        <p>$${p.price}</p>
      </div>
    `).join('');
}

DEMO 5. Xử lý Lỗi

Fetch không tự throw error khi gặp 404, ta phải check response.ok.

check_error.js
fetch('.../posts/999999') // ID không tồn tại
  .then(res => {
    if (!res.ok) {
        throw new Error('Lỗi mạng: ' + res.status);
    }
    return res.json();
  })
  .catch(err => alert(err.message));

Chrome DevTools (Tab Network)

Quy trình kiểm tra Request:

  1. Mở DevTools: F12 hoặc Ctrl+Shift+I.
  2. Chọn tab Network.
  3. Tích vào Fetch/XHR để lọc API.
  4. Reload trang hoặc thực hiện hành động (click nút).
  5. Click vào tên request để xem chi tiết (Headers, Preview, Response).
